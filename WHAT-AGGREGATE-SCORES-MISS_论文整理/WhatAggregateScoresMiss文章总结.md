# WhatAggregateScoresMiss 文章总结

> 论文：*What Aggregate Scores Miss: Measuring Item-Level Regressions in Commercial LLM API Migrations*（Xiaonan Xu, Wenjing Wu；Georgia Institute of Technology / University of Colorado Boulder；arXiv:2608.17719，2026 年 8 月）

## 1. 研究问题

| 内容 | 原文依据 |
|---|---|
| 核心问题：商用 LLM API 升级时，聚合基准分数把异质的逐题行为压缩成一个净值；这种压缩掩盖了什么？聚合分数能否可靠反映升级的向后兼容性？ | Abstract；§1；§3.1 |
| 子问题：RQ1 每条升级边上有多少比例的题可靠改善、多少可靠退化（超出采样噪声）；RQ2 聚合变化与逐题变化的关系、聚合掩盖了多少双向变化；RQ3 同一批回复在 strict 与 loose 判分下升级结论如何变化。 | §3.1 |
| 形式化目标：对边 s→t，每基准报 Δ = mean_i(p̂_{t,i}) − mean_i(p̂_{s,i})、可靠改善份额 P+、可靠退化份额 P−、P_chg = P+ + P−；IFBench 另报 R_m（loose − strict 均值差）与 ΔR = R_t − R_s。 | §3.6 |

## 2. 研究对象

| 内容 | 原文依据 |
|---|---|
| 被测量对象：三条升级边（GPT-5.4→GPT-5.5、GPT-5.5→GPT-5.6 Sol、GPT-5.4→GPT-5.6 Sol）上 900 道题的逐题通过概率变化；不优化任何东西。 | §3.2；§3.3 |
| 方法本身：重复采样（K=50）估计每题每模型通过概率 → Fisher 精确检验 + BH FDR 5% + 实际显著阈值 ε=0.2 做逐题四分类 → 以 1,000 次标签置换的零假设校准 → 与单次抽样比较；IFBench 上另做 strict/loose 对比。 | §3.6；§4.4 |
| 任务领域：研究生级知识问答（SuperGPQA）、奥数（Omni-MATH hard）、可验证指令遵循（IFBench）；均为单轮、可自动判分。 | §3.3 |
| 底层模型：gpt-5.4、gpt-5.5、gpt-5.6-sol；reasoning effort 固定 medium；temperature 不可设；无输出长度上限。 | §3.2 |
| 优化器 / 判官 / 专家模型：无优化器、无 LLM 判官；判分为确定性解析器（知识/数学）与 IFBench 官方验证器（strict 与 loose）。 | §3.5 |

## 5. 研究方法

| 内容 | 原文依据 |
|---|---|
| 分析循环：采集（每题每模型 K=50 次独立单轮调用）→ 离线确定性判分（六类归类；strict 为主）→ 每题 Fisher 精确检验（2×K 表）→ 每 cell 内 BH FDR 5% → ε=0.2 阈值 → 四分类（可靠改善 / 可靠退化 / 实际等价 / 不确定）→ 置换零假设校准。 | §3.4–§3.6 |
| 关键设计：把升级当作"客户端代码不变、依赖版本变动"的依赖升级来测；先用预定义筛选保证题目有 headroom；统计显著与最小效应量双重标准；对整套分类流程（而非单个检验）做置换校准；发布完整回复档案以便不重新调用可变的商用 API 即可复算。 | §3.2；§3.3；§3.6；Data Availability |
| 接受/选择规则：可靠改善/退化 = BH 校正后显著且 \|p̂_t − p̂_s\| ≥ 0.2，按符号分类；实际等价 = 差值 95% CI 完全落在 (−0.2, 0.2)；其余为不确定。可靠变化只在超过零假设 95 分位时才声称。 | §3.6 |
| 规模：900 题 × 3 模型 × 50 次 = 135,000 条回复；9 个 cell，共 2,700 个题–边对；置换 1,000 次。 | §3.3；App. D；Table 4 |
| 评估设计：主分析（Table 1、Fig. 1）；置换校准（§4.2）；IFBench strict/loose（§4.3）；补充分析——单次抽样对比、ε 敏感性、token 消耗、六类回复、难度分层。 | §4 |
| 统计显著性检验：每题 Fisher exact test（2×K），Benjamini–Hochberg FDR 5%（每个 migration–benchmark cell 内），实际显著阈值 ε=0.2，差值 95% 置信区间用于判等价，1,000 次标签置换零假设。 | §3.6 |
| 重复次数 / 随机种子数：主采集每题每模型 K=50；筛选 K=10；单次抽样对比"固定种子"随机抽 1 次（种子值未说明）；置换 1,000 次。 | §3.2；§3.3；App. B；§3.6 |

## 6. 主要结论

| 结论 | 原文依据 |
|---|---|
| 9 个 cell 全部同时存在可靠改善与可靠退化。5.4→5.5 边三基准聚合均升（+2.3 / +7.3 / +1.9 pp），但分别有 5.0% / 6.0% / 8.3% 的题可靠退化。 | Table 1；§4.1 |
| 5.5→Sol 边三基准分化：SuperGPQA +1.4，Omni-MATH hard −4.1，IFBench −3.9；两个下降的基准仍有 9.0% / 6.7% 的题可靠改善。 | Table 1；§4.1 |
| 直接边 5.4→Sol：SuperGPQA 增幅最大（+3.8，P+ 10.8%）；IFBench 净损 −2.0，13.3% 可靠退化、10.7% 可靠改善。直接边的可靠变化份额不等于两条连续边之和，逐题变化在连续升级间相互抵消。 | Table 1；§4.1 |
| 置换校准：零真实变化下 P_chg 的 95 分位在所有 cell 为 0.0%，即 Fisher/BH/ε 标准在 1,000 次置换中未产生任何虚假可靠变化；观测到的 12.0–24.0% 可靠变化份额全部高于噪声底线，与开源 7–8B 模型 K=10 下报告的 21–28% churn 量级相当。 | §4.2 |
| IFBench strict–loose 差距 R_m：GPT-5.4 6.3、GPT-5.5 5.1、Sol 9.0 pp；ΔR：5.4→5.5 −1.2、5.5→Sol +3.9、5.4→Sol +2.7。5.5→Sol 边 strict 掉 3.9 pp 而 loose 只掉 0.04 pp，退化集中在精确约束遵守。IFBench 格式失败计数 945 / 771 / 1352（5.4 / 5.5 / Sol）。 | §4.3；App. E；Table 8 |
| 单次抽样完全检不出可靠变化：两个单次二元观测在 Fisher/BH 下永远不显著，457 个可靠变化一个都不能从单次抽样恢复；聚合 9 个 cell，单次 I→C 翻转 221 个，其中 120 个属可靠改善；C→I 翻转 175 个，其中 87 个属可靠退化；实际等价的 1,868 个题–边对中仍有 51 个单次翻转（25 I→C + 26 C→I）。 | §5；App. B；Table 3；Table 4 |
| ε 敏感性：ε 从 0.10 到 0.25，各 cell 的 P_chg 随 ε 增大而不增（0.10 与 0.15 多数 cell 相同；如 Omni-MATH hard 5.4→5.5 从 25.0% 到 18.0%）；四个 ε 下各 cell 的 P+ 与 P− 均非零，但原文对结论是否变化未说明。 | App. C；Table 5 |
| token 消耗随版本变化：Omni-MATH hard 每请求平均总 tokens 从 8098.1（5.4）降到 4150.1（5.5）（−3948.0）；IFBench 5.5→Sol 从 1357.1 升到 1847.0（+489.8）；SuperGPQA 各边均小幅下降。 | Table 6；Table 7 |
| 难度分层：SuperGPQA easy / middle / hard 在 5.4→Sol 为 +8.4 / +2.7 / +0.1，hard 层在 5.5→Sol 为 −1.0；小样本学科（Law 6 题、Military Science 4 题）波动达 ±20 pp 以上。 | Table 9；App. F |
| 结论：仅凭聚合分数做升级决策会漏掉大量双向逐题变化；聚合上升的 6 个 cell 中 4.4–8.3% 题可靠退化；升级风险取决于对输出的验收标准（strict vs loose），应同时报两种读数。 | §5；§7 |

## 7. 适用条件

| 内容 | 原文依据 |
|---|---|
| 题目需对所研究模型保留 headroom（每题都全对或全错的题不含升级变化信息）；论文用预定义筛选（≥35% 题的准确率落在 [0.1, 0.9]）选基准。 | §3.3 |
| 需要可自动、确定性判分的任务；对下游按程序解析输出的系统，格式不合规即功能回归，应按 strict 计；容忍格式变化的消费者兼容成本更小。 | §3.5；§5 |
| 需要重复采样（本文 K=50）与置换校准才能区分真实变化与采样噪声；单次抽样不可用于逐题回归判定。 | §3.6；App. B；§5 |
| 作者建议：把模型升级当作依赖升级的组织可把本文的逐题退化份额作为设计自家验收测试的参考率；发布的档案可用于不重新调用 API 的复算与改判。 | §5；Data Availability |
| 所需算力/费用：135,000 次 API 调用（900 题 × 3 模型 × 50 次），并发 36，历时约两周；每请求 token 见 Table 6（Omni-MATH hard 上 GPT-5.4 平均 8098.1 tokens/请求，P95 20779）；美元费用：未说明；筛选阶段另有 11 基准 × 30 题 × 3 模型 × 10 次。 | §3.4；App. D；Table 6；App. A |

## 8. 研究局限

| 局限 | 原文依据 |
|---|---|
| 作者写到：基准经 headroom 筛选，报告的可靠变化份额是"信息性基准"上的估计，不是任意负载的总体率。 | §6 |
| 作者：只覆盖一个厂商产品线（GPT-5.4 至 GPT-5.6 Sol）和三个公开基准；其他厂商、任务类型、生产负载可能不同。 | §6 |
| 作者：ε=0.2 与 K=50 共同决定可检出幅度，更小的真实变化被归入"不确定"（Incon. 7.6–24.7%）并如实报告。 | §6；Table 1 |


| 未评估：agentic / 多轮 / 工具调用任务；任何 harness；K 在 1 与 50 之间（如 5、10）时的检出功效；退化原因分析仅有 strict/loose 一个切面；开源或小模型（仅引用 [3] 的 7–8B 结果作对比）。 | §3.2；§4.2；§4.4；§6 |
